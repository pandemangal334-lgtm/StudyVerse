ADDED EXPLANATION

Peterson's Solution — two processes

Assume two processes, P0 and P1. Each process declares its intention using flag[], then gives the other process priority using turn.

Shared: boolean flag[2] = {false, false}; int turn; Process Pi (j = 1 - i): flag[i] = true; turn = j; while (flag[j] && turn == j) { /* wait */ } /* critical section */ flag[i] = false; /* remainder section */

Teaching pseudocode for the classic two-process algorithm. Real-world modern CPU memory-ordering details are outside this introductory model.

ADDED EXPLANATION

Semaphore quick model

wait(S): atomically acquire/decrement S; block if unavailable signal(S): atomically release/increment S; wake a waiter if needed

The PDF describes wait (P/down) and signal (V/up). Exact implementation details vary by semaphore convention; for exams, explain the atomic operation and the effect on waiting processes.

ADDED WORKED EXAMPLE

Banker's Algorithm: Need matrix

Core formula shown by the PDF on page 38:

Need = Max − Allocation

Example only (not from PDF): if a process has Max = (7, 5, 3) and Allocation = (0, 1, 0), then Need = (7, 4, 3).

To decide whether a state is safe, repeatedly find a process whose Need is no greater than currently Available; pretend it finishes, then add its Allocation back to Available. If all processes can finish, the state is safe.

Producer–Consumer

Producer → [ Shared Buffer ] → Consumer

Producer adds items; consumer removes them. Synchronization prevents overflow (adding to full buffer) and underflow (removing from empty buffer).

PDF · PAGE 19

Readers–Writers

Many readers OR one writer
at a time

Many readers may read together; writing needs exclusive access. Reader preference can make writers wait; writer preference prioritizes updates.

PDF · PAGE 21

Dining Philosophers

5 philosophers around a table
Each needs 2 neighbouring chopsticks

If everyone holds one chopstick and waits for the second, deadlock may occur. Starvation means a philosopher may wait indefinitely.

PDF · PAGE 24

Resource cycle example

P1 holds R1 → requests R2
P2 holds R2 → requests R1

Both wait for the resource held by the other. This is the PDF's simple deadlock example.

PDF · PAGE 38

Banker's components

  • Available: free instances now
  • Max: maximum declared demand
  • Allocation: resources currently assigned
  • Need: remaining demand = Max − Allocation

Four necessary deadlock conditions

  1. Mutual exclusion: at least one resource is non-shareable.
  2. Hold and wait: a process holds resources while requesting more.
  3. No preemption: resources cannot simply be forcibly taken away under the condition.
  4. Circular wait: a cycle of processes waits for resources held by one another.

The PDF discusses breaking at least one condition as the basis of prevention (pp. 30–33).
